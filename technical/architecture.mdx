## Navigation Architecture

CalPal uses Expo Router with a tab-based navigation pattern defined in `app/(tabs)/_layout.tsx:11`:

<CodeGroup>
```tsx app/(tabs)/_layout.tsx
import { Tabs } from 'expo-router';
import { HapticTab } from '@/components/ui/HapticTab';
import { IconSymbol } from '@/components/ui/IconSymbol';

export default function TabLayout() {
  const colorScheme = useColorScheme();

  return (
    <Tabs
      screenOptions={{
        tabBarActiveTintColor: Colors[colorScheme ?? 'light'].tint,
        headerShown: true,
        tabBarButton: HapticTab,
        tabBarBackground: TabBarBackground,
      }}>
      <Tabs.Screen
        name="index"
        options={{
          title: 'Home',
          tabBarIcon: ({ color }) => <IconSymbol size={28} name="house.fill" color={color} />, 
        }}
      />
      <Tabs.Screen
        name="restaurant"
        options={{
          title: "Restaurant",
          tabBarIcon: ({ color }) => <IconSymbol size={28} name="fork.knife" color={color} />, 
        }}
      />
      <Tabs.Screen
        name="analytics"
        options={{
          title: 'Analytics',
          tabBarIcon: ({ color }) => <IconSymbol size={28} name="chart.bar.fill" color={color} />, 
        }}
      />
      <Tabs.Screen
        name="profile"
        options={{
          title: 'Profile',
          tabBarIcon: ({ color }) => <IconSymbol size={28} name="person.crop.circle" color={color} />, 
        }}
      />
    </Tabs>
  );
}
```
</CodeGroup>

<Info>
  The navigation includes haptic feedback via `HapticTab` for enhanced user experience on iOS devices.
</Info>

## Data Flow Architecture

<Steps>
  <Step title="User Interaction">
    User scans a barcode or inputs food manually via UI components
  </Step>
  
  <Step title="Redux Action Dispatch">
    Component dispatches Redux action (e.g., `addLog`, `setUserProfile`)
  </Step>
  
  <Step title="State Update">
    Redux reducer updates the centralized state in `store/`
  </Step>
  
  <Step title="Database Persistence">
    Thunk middleware saves to WatermelonDB for offline persistence
  </Step>
  
  <Step title="UI Re-render">
    Components subscribed to state automatically re-render with new data
  </Step>
</Steps>

<Note>
  CalPal follows a **local-first architecture**: all data is stored locally in WatermelonDB first, ensuring the app works completely offline. Cloud sync via Supabase is an enhancement, not a requirement.
</Note>

## Component Architecture

CalPal's component structure separates concerns into:

1. **Screen Components** (`app/`): Route-level components that orchestrate data and layout
2. **Modal Components** (`components/`): Self-contained overlays for specific workflows
3. **UI Components** (`components/ui/`): Reusable, styled primitives (themed text, icons, tabs)
4. **Custom Hooks** (`hooks/`): Shared logic for AI, theming, and color schemes

### Modal-Driven Workflows

Key user workflows are encapsulated in modal components:

- **FoodLogModal**: Add/edit food entries with nutrition data
- **BarcodeScannerModal**: Scan product barcodes via camera
- **ProfileModal**: Update user health metrics
- **AiInputModal**: Natural language food input with AI parsing
