## Overview

CalPal features a beautiful, modern interface that automatically adapts to your device's appearance settings. The app supports both light and dark modes with carefully crafted color schemes for optimal readability and comfort.

<Info>
  CalPal automatically detects your system theme preference and applies the appropriate color scheme without requiring any manual configuration.
</Info>

## Theme System Architecture

CalPal uses a centralized color system defined in `constants/Colors.ts` that provides consistent theming throughout the app.

### Color Scheme Structure

The app maintains separate palettes for light and dark modes:


## Automatic Theme Detection

CalPal uses the `useColorScheme` hook to detect your device's current appearance setting:

```typescript
import { useColorScheme } from '@/hooks/useColorScheme';

const colorScheme = useColorScheme() ?? 'light';
```

This hook monitors your device settings in real-time. When you change your system theme:

1. The hook detects the change immediately
2. Components re-render with the new color scheme
3. All UI elements update their colors automatically
4. No app restart required

<Note>
  If the system theme cannot be detected, CalPal defaults to light mode for optimal compatibility.
</Note>

## Theme Colors Explained

Understanding the semantic meaning of each color token helps ensure consistent theming:

| Color Token | Purpose | Light Mode | Dark Mode |
|-------------|---------|------------|------------|
| `text` | Primary text content | Dark gray | Light gray |
| `background` | Main screen background | White | Dark charcoal |
| `card` | Card and panel backgrounds | Light gray | Medium charcoal |
| `tint` | Primary accent color | Teal | White |
| `icon` | Icon tinting | Medium gray | Soft gray |
| `tabIconDefault` | Inactive tab icons | Medium gray | Soft gray |
| `tabIconSelected` | Active tab icons | Teal | White |

## How Components Use Theming

All CalPal components dynamically reference the `Colors` object to ensure they adapt to the current theme.

### Example: Profile Screen

Here's how the Profile screen (`app/(tabs)/profile.tsx`) applies theming:

```typescript
import { Colors } from '@/constants/Colors';
import { useColorScheme } from '@/hooks/useColorScheme';

const colorScheme = useColorScheme() ?? 'light';

// Icon with theme-aware color
<Ionicons 
  name="person-circle" 
  size={80} 
  color={Colors[colorScheme].tint} 
/>

// Button with dynamic background
<Pressable 
  style={{ 
    backgroundColor: Colors[colorScheme].tint,
    borderRadius: 8,
    padding: 8 
  }}
>
  <Text style={{ color: Colors[colorScheme].background }}>Edit</Text>
</Pressable>
```

### Dynamic Styling Pattern

The pattern used throughout the app:

<Steps>
  <Step title="Import Dependencies">
    Import the `Colors` constant and `useColorScheme` hook at the top of your component.
  </Step>
  
  <Step title="Get Current Scheme">
    Call `useColorScheme()` to get the current theme (`'light'` or `'dark'`).
  </Step>
  
  <Step title="Reference Colors Dynamically">
    Access colors using bracket notation: `Colors[colorScheme].propertyName`
  </Step>
  
  <Step title="Apply to Styles">
    Use the color values in your component styles, either inline or in StyleSheet objects.
  </Step>
</Steps>

## Theme Consistency

Every screen and component in CalPal uses the same theming system for a cohesive experience:

- **Navigation tabs**: Active and inactive states adapt to theme
- **Modal dialogs**: Background and text colors switch appropriately
- **Input fields**: Border and placeholder colors adjust for visibility
- **Cards and panels**: Subtle elevation through theme-appropriate shading
- **Icons and buttons**: Accent colors provide clear visual hierarchy

### Example: Modal Theming

The profile edit modal demonstrates comprehensive theming:

```typescript
<Modal visible={editModalVisible} animationType="slide" transparent>
  <View style={styles.modalOverlay}>
    <View style={[
      styles.modalContent, 
      { backgroundColor: Colors[colorScheme].card }
    ]}>
      <TextInput
        style={[
          styles.manualInput,
          { 
            backgroundColor: Colors[colorScheme].background,
            color: Colors[colorScheme].text,
            borderColor: Colors[colorScheme].tint
          }
        ]}
        placeholderTextColor={Colors[colorScheme].icon}
      />
    </View>
  </View>
</Modal>
```

Notice how multiple theme tokens are used:
- `card` for modal background
- `background` for input fields
- `text` for input text
- `tint` for borders
- `icon` for placeholder text

## Accessibility Considerations

CalPal's theme system is designed with accessibility in mind:

<Note>
  Both light and dark mode color palettes meet **WCAG AA contrast standards** for text readability.
</Note>

### Contrast Ratios

- **Light mode text**: 13.8:1 contrast ratio (Dark gray on white)
- **Dark mode text**: 13.1:1 contrast ratio (Light gray on dark charcoal)
- **Both modes exceed**: WCAG AAA standard (7:1) for normal text

### Visual Comfort

- **Dark mode**: Reduces blue light exposure in low-light environments
- **Light mode**: Provides excellent readability in bright conditions
- **Smooth transitions**: Theme changes don't cause jarring flashes

## Developer Reference

For developers working with CalPal's theme system:

**Color definition location**: `constants/Colors.ts`

**Hook location**: `hooks/useColorScheme.ts`

**Usage pattern**:
```typescript
const colorScheme = useColorScheme() ?? 'light';
const backgroundColor = Colors[colorScheme].background;
```

**Best practices**:
- Always provide a fallback value (`?? 'light'`) when using the hook
- Use semantic color names (`tint`, `card`) rather than specific colors (`blue`, `gray`)
- Test all screens in both light and dark modes
- Ensure sufficient contrast for text and interactive elements
